## Will a friend's `git clone` just work?

**For the extension itself — yes, no setup needed:**
1. `git clone <repo-url>`
2. Chrome → `chrome://extensions` → enable **Developer Mode** (top-right)
3. **Load unpacked** → select the `EXTENSION/` folder
4. Done. The trained model (`EXTENSION/lib/vocab.json`, ~7.7MB) is already
   checked in — no training step, no `npm install`, no build step. It's
   plain JS/HTML/CSS.

**For `TRAINING/` (only needed to *retrain* the model) — no, needs setup:**
Python 3 + `cd TRAINING && python -m venv .venv && pip install -r
requirements.txt`. A friend who just wants to *use* the extension never
needs to touch this folder at all.

## What changed this session (chronological summary)

All of this is in `EXTENSION/` unless noted.

1. **Negation highlighting** — `modules/result_display.js` and
   `popup/popup.js` now also highlight the negation trigger word itself
   ("not") alongside the word it flips ("beautiful"), not just the flipped
   word alone.
2. **Fixed a false "aggressive" highlight** — a genuinely positive word
   (e.g. "beautiful") could render red in the on-page/Steps-tab word
   highlighter purely from Naive Bayes' noisy, class-imbalanced word
   counts (aggressive-class training data is ~3.75x smaller than safe, so
   rare words get inflated log-likelihoods there). Added a guard
   (`VADER.isPositiveLexiconWord`) in `result_display.js` and `popup.js`
   so a known-positive, non-negated word is never painted as an aggression
   signal. **This only changes the visual highlight — the actual NB/VADER/
   Hybrid percentages are untouched.**
3. **Popup restructure** — added a new **Algorithms** tab (Detection →
   Test → Steps → Algorithms → Evaluation → Settings) covering:
   - "How Naive Bayes Works" / "How VADER Works" — step-by-step derivations
     with real numbers from this model (not generic textbook formulas).
   - "Why 60% Naive Bayes / 40% VADER?" — see **Open item #2** below before
     citing this to anyone.
   - "Worked Examples — Aggressive vs. Safe" — two fully hand-verified,
     real walkthroughs: *"You are not beautiful"* (NB 25.0% / VADER 54.8% /
     Hybrid 54.8% → AGGRESSIVE, via the zero-evidence guard) and *"You are
     so beautiful"* (NB 36.2% / VADER 0.0% / Hybrid 21.7% → SAFE) — same
     sentence, one negation removed, everything else held constant.
   - Evaluation tab gained a **Dataset Composition** table: 64,900 total
     comments, 16,225 aggressive (25.0%) / 48,675 non-aggressive (75.0%),
     same ratio preserved in the 51,920/12,980 train/test split. Verified
     against `vocab.json`'s `class_counts` and `sop2_report.txt`.
   - Test tab's live per-comment breakdown now explicitly names the real
     JS functions doing the math (`Math.log()`, `Math.exp()`, `Math.sqrt()`,
     `Math.max()`) and clarifies that NB's and VADER's sign conventions for
     "positive/negative" are opposite each other — a real point of
     confusion if you're defending this to a panel.
4. **Dark mode** — Settings-tab theme picker was tried first, then moved
   per your request to a single cycling icon button in the header (next to
   the on/off switch): Light → Dark → Auto, saved to `chrome.storage.local`,
   "Auto" follows `prefers-color-scheme` live. Dark palette uses true
   neutral grays (not the blue-tinted "slate" scale — you flagged the first
   version as too navy). Brand colors (greens/reds used as button fills
   with white text) are deliberately *not* re-tinted per theme — see the
   comment above `:root[data-theme="dark"]` in `popup/popup.css` for why.

## Known open items — not yet fixed

1. **Self-distress dampening has a real gap.** `content.js`'s
   `isSelfDirectedDistress()` (mirrored in `popup.js`'s injected test
   script) is supposed to cut the score of self-directed venting like *"I
   feel so worthless lately"* by 60% (`SELF_DISTRESS_DAMPEN = 0.4`) so it
   doesn't get treated as an attack on someone else. It currently **fails
   to do this** — the `PERSON_INSULT_WORDS` gate rejects *any* comment
   containing a word like "worthless"/"stupid" outright, even when no
   second-person or third-party marker is present and "I" is the only
   possible subject. Discussed fix (not applied): only reject on an insult
   word when there's *also* another-directed marker, or require the
   first-person word to be a bare subject ("i am/feel") immediately near
   the insult word rather than just anywhere in the sentence — the latter
   is needed because a blanket removal of the gate would introduce a
   *new* false negative ("my teacher is worthless" would wrongly read as
   self-directed). Needs a decision, then a matching fix in **both**
   `content.js` and `popup.js` (and ideally `TRAINING/train.py`'s
   `is_self_directed_distress()` too, to keep Python/JS in sync per the
   README's "fix logic in both places" rule).
2. **The 60/40 hybrid weight has no formal derivation anywhere in this
   repo.** Every reference to it (`train.py`, `content.js`, `vader.js`,
   `sop2_report.txt`, the notebook) either states the formula or says it
   "matches the manuscript" (Chapter 3) — but that manuscript document is
   not part of this codebase, so its actual reasoning is unverifiable from
   code alone. The Algorithms tab now explains 60/40 via (a) it being close
   to the ratio of standalone F1 scores (81.19/(81.19+57.91) ≈ 58.4%) and
   (b) your own observation that increasing VADER's weight empirically
   made results worse. **If your actual thesis manuscript has a different
   or more rigorous derivation, that's the authoritative answer for your
   defense — check it before relying on the in-app explanation alone.**
